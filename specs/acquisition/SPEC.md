# 研报获取（下载与扫描）

## 责任

把研报从外部搬到本地，并把手上的本地文件变成索引管线可消费的「研报记录」。

- **下载**（`yanbao/downloader.py`）：调东方财富列表接口分页取研报条目，下载 PDF，写出元数据 JSON；维护下载去重状态、自适应限流、损坏 PDF 清单。
- **扫描**（`yanbao/scanner.py`）：遍历数据目录里的研报 JSON，解析出统一字段并计算内容哈希，判定哪些是新研报、哪些有变更。

## 边界

允许依赖配置（数据目录、损坏 PDF 清单路径）。**不得触碰 SQLite、不得写 `text_chunks`**：本模块只管「文件在磁盘上」，入库由索引管线负责。

下载与扫描互不依赖：扫描只认磁盘上的文件，不知道网络；下载只管产出文件，不知道数据库。

## 决策与不变量

- **两种哈希各有其职**：`info_code` 的 MD5 是下载去重键（写入数据目录下的 `.download_state.json`，只用于「这篇下过没有」）；JSON 文件内容的 MD5 是 `file_hash`，用于增量索引判定内容是否变更。两者不可互换。
- **先写元数据再下 PDF**：PDF 下载失败时元数据 JSON 仍然保留，该篇计为失败而不是丢弃——重下时不必重新抓列表。
- **限流是硬要求**：2 秒滑动窗口控速，叠加自适应退避——HTTP 429/403 退避翻倍（上限 16 倍），5xx 退避加一，连续 10 次成功则退避减半。东方财富对高频请求会直接拒绝，下载必须慢。
- **损坏 PDF 有独立台账**：抽取失败的 PDF 记入 `corrupted_pdfs.jsonl`（含 code、路径、错误、时间）。下载时跳过台账中已有的研报，`fix` 流程据此重下并重写台账。
- **文件名是展示名**：本地路径按「券商目录 / 日期_标题」组织，标题过滤掉文件系统不友好的字符并截断到 60 字。
- **编码要兜住**：扫描 JSON 时依次尝试 utf-8、gbk、gb18030，全部失败再用 chardet 猜测，仍失败才跳过该文件。

## 已知缺口

- `requests` 被下载器使用，但未在 `pyproject.toml` 与 `requirements.txt` 中声明（已确认）；安装依赖需要显式补上，否则干净环境下会在导入期失败。
