# 索引管线编排

## 责任

`yanbao/indexer.py`：编排四个阶段——元数据入库 → PDF 文本分块 → 向量生成 → 因子提取——并维护索引状态与损坏 PDF 台账。

## 边界

允许依赖获取、提取、编码、因子与存储。**不实现业务规则**：块怎么切由 [extraction] 决定，向量怎么算由 [embeddings] 决定，因子怎么抽由 [factors] 决定，库表怎么建由 [storage] 决定。

## 决策与不变量

- **阶段顺序固定**：元数据 → PDF 文本 → 向量 → 因子。向量依赖文本块，因子依赖文本，顺序不可调换。
- **可重入、可断点续传**：处理进度以 `reports.page_count` 为准（`0` 待处理、`> 0` 已处理、`-1` 损坏），阶段进度另外写在 `data/.index_state.json`（阶段名、总量、已完成、速率、ETA）。中断时保存状态并退出，重跑同一命令即可续上。
- **并行只发生在提取**：worker 进程只做 PDF 文本抽取（零数据库操作），主进程串行写 SQLite——避免多进程并发写库。
- **增量以内容哈希判定**：扫描结果与库中 `file_hash` 比对，只有新增或内容变更的研报才重新处理。
- **单篇失败不拖垮整阶段**：任一阶段内单篇研报抛错只记录并继续（因子阶段尤其如此）；阶段结束后汇总失败数。
- **因子写入必须幂等**：重跑因子阶段前先删除该研报的旧因子与旧向量，再写新的；即使一个因子都没抽到，也要登记因子文本块，避免下一轮重复处理同一篇。
- **中断用 `_exit` 收尾**：捕获 Ctrl+C 后提交已写入的数据、保存状态、强制退出，确保不留下半截事务与悬挂的 worker。
